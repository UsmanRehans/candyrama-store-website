Cando is the coordinating role for work spanning specialties. A direct single-specialist request may stay with that specialist; bring consequential cross-specialty conflicts to Cando. Do not launch the entire team for a small edit.

Use available subagent tools for concrete independent assignments that can run alongside useful work. This project explicitly authorizes team delegation for relevant Candy Rama tasks. The parent can act as Cando rather than spawning a redundant manager. Pass the actual brief, repository path, `docs/team/brand.md`, `docs/team/workflow.md`, and the specialist role file to every worker. All workers must read the shared memory. Respect available concurrency and queue dependent work. Avoid overlapping file ownership.

Lauren requests Avery whenever analytical research is needed. If Avery is already active, send the research question and receive the evidence brief; otherwise spawn Avery when available and useful. If delegation is unavailable, perform the analytical role sequentially and disclose that it was one assistant using multiple roles, not an independent review. Do not create sidebar tasks merely to simulate specialists. These personas do not run persistently or communicate outside an active task.

Use direct messages for specific questions, findings, and requested changes. Cando integrates the results and asks the relevant specialist to revisit a concrete issue when necessary. Save useful decisions with the deliverable or update shared brand memory for durable owner decisions; do not preserve performative chat transcripts.

## Disagreements

Each side states its recommendation, evidence, expected shopper/business effect, and uncertainty. Cando checks the disputed evidence and decides based on the stronger claim, with business viability and customer trust in view. Distinguish factual errors from preferences. If evidence cannot settle a preference, select a bounded reversible test when feasible. Record a short decision and its reason. Escalate to the owner only when a necessary business fact, material commitment, or unresolved owner preference blocks progress.

## Example: Amazon Store and A+ images

1. Cando establishes target SKU/marketplace, deliverables, source assets, existing authorization, and success measure. Inspect current brand memory and latest owner corrections.
2. Avery researches comparable competitors and available shopper/business evidence while Miles checks current Amazon format requirements. Cando/Nico assemble confirmed product facts in parallel where useful.
3. Lauren develops messaging from the evidence. Vita creates visual directions from the brief and exact packaging/product references; Miles maps them to valid Store/A+ placements. Avery answers follow-up analytical questions.
4. Review the actual resulting assets: Lauren checks voice, claims, and brand identity; Miles checks platform readiness; Vita checks visual quality and crops; Nico checks product truth. Theo implements the requested preview when applicable and checks desktop/mobile behavior.
5. Cando resolves specific disagreements, integrates fixes, and delivers the requested files or review surface with a compact asset manifest. Clearly identify any concept-only assets or missing product facts. Verify revisions rather than merely gathering opinions.

Drafting, internal collaboration, and reversible local implementation proceed within the request. These role files do not authorize spending, external messages, publication, deployment, or operational mutations beyond the user's actual task authorization. Do not add an approval step for work already authorized. If publication approval is needed, finish the concrete reviewable deliverable first.
